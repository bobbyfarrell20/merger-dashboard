# Tesla × SpaceX merger announcement tracker (draft)

A static site: `index.html` plus `data/*.json`. Charts use Chart.js from a CDN. Nothing has been published yet.

## Files
- `data/config.json`: rules-model settings: prior, signals (log-odds), regimes, weekday and event multipliers, calendar events, alert thresholds. **Edit this to change the model.**
- `data/judgment.json`: hand-set judgment anchors with a dated rationale.
- `data/news.json`: headlines grouped by ET day, each with source link, time, factor tag and an odds note. Backfilled by hand from Sept 18 with cited sources; `update.py` appends Google News RSS hits (tagged `auto: true`, review them).
- `data/event_log.json`: curated event log.
- Generated by `update.py`: `live.json` (prices, options, EDGAR, markets), `model.json` (daily curve, expiries, weeks, headline, deltas, alerts), `history.json` (daily snapshots for "since yesterday" changes).

## Model
1. **Horizon:** P(announcement by Jun 30, 2027) = logistic(logit(prior) + Σ active signal log-odds). Prior 0.45. Signals: AGM silence +0.30, retail auto-vote +0.15, credit facility +0.05, Musk hints +0.10, no leaks −0.40. Two switches are off for now: routine AGM date −1.0 and special committee +1.5. Current result ≈ 50%.
2. **Timing:** each day's weight = weekday × regime × event multipliers. Blackouts: unlock ×0.05, Starship launch ×0.1, Tesla event ×0.1, index rebalance ×0.1, holiday ×0.15, earnings ×0.3. Pre-earnings quiet period ×0.7. Day after a clean catalyst ×1.8. Regimes: last same-ballot window Oct 14-20 ×1.3, holidays ×0.7. Daily hazard = k × weight, with k solved so cumulative probability hits the horizon number.
3. **Judgment:** cumulative anchors, interpolated using the rules model's daily shape.
4. **Markets:** Polymarket (any official announcement) and Kalshi (definitive agreement only), linearly interpolated between contract dates. Kalshi uses mid-price if the spread is 6¢ or less, otherwise last trade.
5. **Expiries:** cumulative probability from today through each TSLA expiry listed on Yahoo, with ATM IV (average of the two strikes nearest spot), call volume, and IV-inflating events inside the window.

## Running
```
python3 -m venv .venv && .venv/bin/pip install yfinance requests
.venv/bin/python update.py         # live refresh plus recompute
.venv/bin/python update.py --offline  # recompute only
python3 -m http.server 8765        # preview at localhost:8765
```
Schedule it every weekday around 8:30am ET. `model.json["alerts"]` lists watched SEC filings from the past day and any odds move above `config.alerts` thresholds.

Not investment advice.

## Two definitions
- **Def 1, any official announcement** (offer letter, bear hug, special committee formed, or signed deal). This is the rules and judgment curves above. Compare with Polymarket.
- **Def 2, signed merger agreement only.** Compare with Kalshi. Derived from Def 1 in `config.signing_lag`:
  signed_pdf(d) = s·any_pdf(d) + (1−s)(1−q)·Σ_t any_pdf(d−t)·lag(t)
  - s = 0.35: share of announcements that are already a signed deal (Grok's form split).
  - q = 0.15: chance a letter never leads to a signed deal.
  - lag ~ Gamma(shape 2, mean 55 days): median about 46 days, about 80% within 90 days, capped at 240 days.
  - Precedents: Tesla/SolarCity took 41 days from letter to signing; Musk/Twitter took 11 days.
- The same transform turns the judgment curve into its signed-deal version. Headline, expiry, weekly and daily outputs, and the since-yesterday changes, exist for both (`rules_signed_*`, `judgment_signed_*`).
- The page has a toggle: Any / Signed / Side by side.

## Alerts: time decay vs news
Each run compares today with the last snapshot in `history.json`, which stores yesterday's model inputs: signals, calendar, judgment anchors and signing lag.
- **Time decay** = (yesterday's inputs evaluated as of today) − yesterday's odds. This covers days passing without an announcement, the 7/30/90-day windows rolling, and blackouts passing.
- **News** = today's odds − (yesterday's inputs as of today). It's nonzero only when an input changed: a signal flipped or was reweighted, a calendar event was added or removed, a judgment anchor changed, or the config changed.
- An alert fires if any news part is nonzero for either definition. It lists the input changes and that day's headlines. A watched SEC filing also alerts. Pure time decay never alerts.
- Prediction-market moves are shown, but they don't alert by themselves.
- A rules-signal change can nudge the judgment curve slightly, because the judgment curve borrows the rules model's daily shape.
- Results: `model.json` → `split`, `drivers`, `alerts`; also each day's `news.json` entry.

## Scheduling (GitHub Actions)
`.github/workflows/update.yml` assumes this folder is the repo root.
- It runs on weekdays at 12:30 and 13:30 UTC. A guard step only lets the run that lands at 8am New York time go ahead, so the update happens at 8:30am ET in both EDT and EST.
- It installs `requirements.txt`, runs `update.py`, commits any changes under `data/`, and writes alerts to the run summary.
- It's free on a public repo. GitHub's scheduled runs can start a few minutes late.
- It also has a manual "Run workflow" button.

## Intraday watcher (`watch.py`, `.github/workflows/watch.yml`)
- **Schedule:** every 15 min from 07:00 to 20:00 New York time on weekdays, and hourly at all other times.
  - UTC crons cover both the EDT and EST windows. A New York-time check lets only the right trigger run, so there are no duplicates.
  - That's about 63 runs per weekday and 24 per weekend day.
- **Speed:** it uses only the Python standard library (nothing to install), and a run takes about 3 seconds.
- **Checks:**
  - EDGAR submissions for TSLA (CIK 1318605) and SPCX (CIK 1181412): 8-K/A, DEF/PRE 14A, DEFA14A, DEFM14A/PREM14A, PREC/DEFC14A, S-4, F-4, 425, SC 13D(/A), SC TO-T/C, SC 14D9, SC 13E3, DFAN14A, 8-A12B.
  - Google News RSS (past day) for 6 merger queries.
- **Headline filter:** a headline passes only if all of these hold:
  1. It mentions tesla, spacex, spcx, tsla or musk.
  2. It has a deal term: merger, merge, combine/combination, acquire/acquisition, takeover, buyout, all-stock, stock swap, exchange ratio, bear hug, offer letter, special committee, independent directors, definitive agreement, tender offer, fairness opinion, annual/special (shareholder) meeting, proxy statement, go private, roll-up.
  3. It mentions SpaceX/SPCX, or it's Tesla plus a meeting or proxy term.
  4. It has no noise term: price prediction, stock forecast, should you buy, quote, top N, "X vs Y stock", rumor mill, podcast, livestream, how to watch, opinion/op-ed.
  5. Its source is on the allowlist: Reuters, Bloomberg, WSJ, FT, CNBC, Barron's, AP, NYT, WaPo, Axios, The Information, Semafor, Fortune, Business Insider, Yahoo Finance, MarketWatch, Electrek, Teslarati, The Verge, TechCrunch, Ars Technica, Space.com, SpaceNews, Spaceflight Now, IBD, Seeking Alpha, Benzinga, CNN, BBC, Guardian, Forbes, Fox Business, Puck, InsideEVs, Not a Tesla App.
- **Dedupe:** `data/seen.json` is committed in the repo and holds EDGAR accession numbers and normalized headline titles. If it's missing, the first run only records what it sees and sends no alert.
- **On a new hit:**
  - Appends the item to `data/news.json`, tagged `watch: true`, with an "odds not yet re-assessed" note.
  - POSTs `{"items":[{"title","url","source","time_et","type"}]}` to secret `WAKE_WEBHOOK_URL`, with header `Authorization: <WAKE_WEBHOOK_AUTH>` (sent exactly as stored) if that secret is set. `type` is `filing` or `headline`, and `time_et` is "YYYY-MM-DD HH:MM" in New York time. If the secret isn't set, the POST is skipped.
  - It never recomputes any odds.
- **Local testing:** `python3 watch.py --dry-run` prints the payload and writes nothing. `--bootstrap` marks everything currently visible as seen.
- **Market-move alerts:** each watcher run also fetches every open Polymarket and Kalshi merger contract and keeps 14 days of prices in `data/markets_history.json`. Settings are in `config.market_watch`.
  - It sends a `market_move` item when a contract moves `move_pp` points (default 10) against its price about `window_hours` (24) earlier. If there's less history than that, it compares with the oldest stored price.
  - After an alert, it only alerts again once the price moves another `move_pp` points from the alerted price.
  - Price used: the bid/ask midpoint if the spread is 6¢ or less; otherwise the last trade if 24h volume is at least 50; otherwise the quote counts as thin and is stored but never alerts.
  - Extra payload fields: `contract`, `from`, `to` (0–1), `window_hours`.
